# 出貨單價稽核 — 交接說明

> 給接手的 Claude Code：**先讀完這份，再讀 `check_prices.py`。**
> 本資料夾與這個 repo 的股票程式無關，是獨立的出貨對帳稽核工具。

---

## 一、事情的起因

115/08/26 檢查 8 月帳出貨明細表時，發現一筆單價誤植：

| 項目 | 內容 |
|---|---|
| 客戶 | 00716097 互愛中正紀念堂 |
| 出貨單號 | AB1150805007（訂單 POT20260804015） |
| 出貨日 | 0115/08/05 |
| 品項 | 50833058900 香積麵日式味噌4片裝 x 8 |
| 交貨量 | 16 組 |
| 誤植單價 | **391.88**（= 正確價 97.97 × 4） |
| 正確單價 | 97.97 |

**金額影響**

| 欄位 | 帳上 | 應為 | 差異 |
|---|---|---|---|
| 該筆金額 | 6,270 | 1,568 | −4,702 |
| 未稅金額 | 9,112 | 4,410 | −4,702 |
| 稅額 | 456 | 221 | −235 |
| 銷貨金額(含稅) | 9,568 | 4,631 | **−4,937** |

含稅溢收 **4,937 元**，待開折讓單或作廢重開。**接手第一件事是確認這張單處理掉了沒有。**

**為什麼原本沒抓到**：這張單的「未稅金額／稅額／含稅金額」三欄彼此自洽（表頭金額是照錯誤的明細加總出來的），
單價 × 數量 = 金額 也成立。純用試算表公式驗算完全抓不到，**只有拿單價去比對標準價目表才會現形**。

---

## 二、已經查證到什麼程度

比對範圍：**0115/02/24 ～ 0115/08/27，2,368 筆明細、74 家客戶、8 個品項**。

- 全期間只有上述 **1 筆** 單價異常
- 單價 × 數量 = 金額：2,368 筆全部相符
- 同一客戶同品項前後不同價：0 筆
- 74 家客戶一價到底，**沒有客戶別差異定價**（這點很重要，稽核邏輯才能用單一價目表）
- 互愛中正紀念堂在整個期間**只出過這一張單**，沒有更早的紀錄可比對

**1 月及更早無法查核**：ERP 出貨明細表最早只留到 115年3月帳（內含 2/24 起的資料）。
雲端上 1 月只有 `115.01-03月實際出貨.xlsx`，那是各品項箱數彙總，沒有客戶、沒有單價。
要往前追必須從 ERP 重新匯出。

## 三、資料在哪裡（Google Drive）

| 用途 | 位置 |
|---|---|
| 當月帳出貨明細表 | 雲端硬碟主資料夾，檔名 `115.MM.DD(N月帳)出貨明細表.xlsx` |
| 歷史月帳 | `出貨明細表歷史/115年MM月帳/` |
| 每日出貨檔 | `115年MM月/26MMDD.xlsx`（單日，欄位同上） |

**重要特性**：`(N月帳)出貨明細表` 是**當月累計**檔，每天覆蓋新增。
所以每個帳期只要取**最後一份**就代表整個帳期，不必逐日下載。
帳期不等於日曆月（例：3月帳涵蓋 02/24～03/27），跨月是正常的。

檔案結構：每個工作表是一天（表頭列以 `客戶代號` 開頭），欄位為
`客戶代號 / 客戶簡稱 / 訂單編號 / 出退貨日 / 訂單日期 / 出退貨單號 / 發票種類 /
未稅金額 / 稅額 / 銷貨金額(含稅) / 品號 / 品名 / 交貨量 / 單位 / 單價 / 金額 / 折扣金額 / 註`

## 四、怎麼用這套工具

```bash
pip install openpyxl

# 檢查單一檔案
python3 price-audit/check_prices.py 115.08.26\(8月帳\)出貨明細表.xlsx

# 檢查整個資料夾（會自動去重，同一張單出現在多份累計檔只算一次）
python3 price-audit/check_prices.py ./出貨明細表歷史/115年07月帳/
```

全部通過 exit code 0，有異常 exit code 1，方便串排程。

### 五項檢查

1. **單價不符** — 逐筆比對 `price_master.csv` 的標準價（← 這次的錯誤是靠這項抓到的）
2. **金額不符** — 單價 × 交貨量 是否等於金額（容許四捨五入 1 元）
3. **表頭不符 / 稅額不符 / 含稅不符** — 明細合計 vs 未稅金額、稅額是否為未稅 5%、含稅是否等於未稅+稅額
4. **客戶多價** — 同一客戶同品項出現兩種單價
5. **零負值 / 未知品號 / 單位不符**

---

## 五、避免再發生：建議的例行做法

1. **每天出完貨就跑一次**，對當天的 `(N月帳)出貨明細表` 或 `26MMDD.xlsx` 執行 `check_prices.py`。
   異常當天就抓到，還來得及在開發票前改單，不必事後開折讓。
2. **月結對帳前一定跑整個帳期**，作為對帳單寄出前的最後一道關卡。
3. **調價時先改 `price_master.csv`**，不要直接放行。改價目表 → 跑一次 → 確認只有預期中的品項變動。
   價目表有 `生效日` 欄位；若未來出現同品項分階段調價，需要擴充腳本支援日期區間比價（目前是單一價）。
4. **新品上市要補進 `price_master.csv`**，否則會被報成 `[未知品號]`（這是刻意設計的，寧可吵也不要漏）。

### 接手後可以優先做的三件事

- [ ] 確認 AB1150805007 的折讓／重開單已經處理
- [ ] 把 `check_prices.py` 排成每日自動執行，異常時發通知（這個 repo 已經有 `notify.py`，可參考它的通知方式）
- [ ] 若能從 ERP 匯出 115 年 1 月的出貨明細，補跑一次把年初到現在補齊
